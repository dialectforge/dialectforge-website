DialectForge / Lu

Lu Open source · AGPL-3.0

Lu is an experimental AI I wrote from scratch in Rust. It has no neural network and no learned weights. What it knows is stored in a graph you can read: nodes of knowledge joined by typed, weighted bonds. It stays on, keeps what it learns, says “I don't know” when it doesn't know, and carries scars, which are memories of past mistakes. It didn't become a product, and building it broke me financially. This page explains how it works, what has been tested, and what went wrong.

§ 1 The idea

Knowledge you can point at

An LLM answers by running your prompt through billions of fixed weights. What it knows is smeared across all of them, so you can't point at one fact, fix it or remove it. Lu stores each piece of knowledge as its own node with its own 32-byte identity (a seed), and joins nodes with bonds such as IsA, Causes, PartOf and UsedFor. Every answer is a path through that graph, so you can print it.

That makes four things possible that are hard for an LLM: remove one fact without retraining, show the chain behind an answer, refuse when nothing supports an answer, and run on an ordinary CPU. The cost is just as real: Lu only knows what it has been fed. It has no pre-trained prior to fall back on.

A card catalog instead of a hunch. You can pull any card out and look at it.

§ 3 Step by step

How Lu works

  1. It learns by reading

    Lu doesn't train with gradient descent. Extractors split text into sentences and run typed patterns in order (definition, mechanism, composition, purpose, example, contrast, causal), and anything left over is kept as raw text. Ingestion scripts load dictionaries, WordNet, Wikidata, arXiv abstracts and more. An LLM can be a source: its output gets broken into nodes and bonds. Its weights are never used. I called this “the model talks, Lu eats”.

  2. It persists

    The graph lives on disk in an SST-style store: node and bond tables, a write-ahead log, a manifest and a keyword index, with append-only IDs and compaction. Encryption at rest is optional. Lu is meant to stay on and keep learning between sessions, not start fresh each time.

  3. It answers by spreading activation

    Query words pick seed nodes from the keyword index. Activation spreads along bonds with decay at each hop and a ceiling, and large hub nodes are damped so they don't take over. Recall runs twice: once on the question alone, so understanding isn't biased by the conversation, and then again with topic seeds from session memory.

  4. It says “I don't know”

    Before answering, an honesty gate checks the recall. It refuses when the query has no real traction, when only some of the words match (Lu won't make up a link between something it knows and something it doesn't), and when a single word dominates and the rest add nothing.

  5. It reasons and writes

    A thought, action, observation loop and a recall, synthesis and critic chain build the answer. The critic can force a retry. Templates turn the nodes and bonds it reached into prose: definitions, causal “why” answers, side-by-side comparisons. No LLM writes the output. The rule is honest over eloquent. A final off-ness check looks for answers that don't match what the graph supports.

  6. It carries scars

    A scar marks a bond as “don't act on this”, with a reason and a date. During recall a scarred bond carries no weight, so activation can't cross it. The history stays intact, so Lu can say “I know this connection exists, but I was scarred against using it, on this date, for this reason.”

  7. It gets curious

    During recall Lu watches for gaps: dead ends, isolated nodes, “knowledge deserts” and hub boundaries. Confirmed gaps go into a capped wonder queue, and a separate worker researches them later, off the hot path.

  8. It improves itself, carefully

    Bonds that get used are strengthened. Changes made during a session are tagged, so one conversation can't pollute the baseline, and a change is only promoted after it holds up across several separate sessions. Conclusions Lu derives can be written back as inferred bonds, but only when they're corroborated: a bond that was just written can't count as its own proof.

§ 5 Design choices

Why it's built this way

  • A graph instead of weights: so knowledge can be read, edited, revoked and traced.
  • Scars instead of deletion: keeping the history is more honest than erasing it, and Lu can explain why it won't use a connection.
  • No LLM in the output path: anything that writes prose freely can make things up. Templates can only say what was reached.
  • An append-only bond list (44 types): old brains stay readable as types are added.
  • Separate guest and admin binaries: the public HTTP server can only ask questions, because the admin tools aren't compiled into it. Code runs through a separate sandboxed broker.
  • Errors, not empty values: the hardest lesson. A component that quietly returns 0, "" or None when it fails is worse than one that errors.
§ 6 Tested vs unproven

What's tested, and what isn't

Tested: 2,388 Rust tests pass on cargo test (0 failing, 8 ignored). In my own 100-question adversarial runs, Lu made no fabrications, even on questions about invented names; its failures were wrong routing or missing coverage. The parts that worked in my runs: dictionary-based definitions, entity overviews, attribute lookups, comparisons, causal answers, a calculator, a bounded code writer in a sandbox, and geometry answers that are exact or “I don't know”.

Unproven or weak: all the scorecards are mine, on my own brain data, and nobody has reproduced them. Its breadth never came close to an LLM's: in an audit of 20,000 nodes, only about 23% were clean concepts. Lu lists facts well but doesn't reliably chain them into a conclusion. The vision path was a stub. Many design docs describe plans, not shipped features. The trained brain isn't included, so a fresh build starts close to empty.

§ 7 History

What went wrong

  • Breadth: every node had to be earned, and the clean ones leveled off. One large ingestion batch moved zero test questions from fail to pass.
  • Memory: RAM grew with the number of nodes, and decrypting bond blocks used a big share of CPU. Production ran out of memory more than once.
  • Parts that looked fine but weren't connected: features that passed their checks but were quietly switched off because a component returned an empty value on failure.
  • New facts aren't checked for truth: Lu won't invent a fact, but it will repeat a false one it was taught. Some misinformation got through and had to be blocked with a curated denylist.
  • Timelines: my estimates slipped again and again.
  • The server: Lu ran on one rented server with no off-box backup of its trained brain. In October 2026 the server was lost, and the brain data with it. The code was in Git and survived, and that code is what's published.

The parts that held up (structural revocation, the honesty floor and scars) became Cattledog, which wraps any LLM.

The prototype jig broke. The measurements you took with it are still good.

§ 8 Run it

How to run it

git clone https://github.com/dialectforge/lu
cd lu
cargo build --release
cargo test        # 2,388 passing
# then ingest your own data: see scripts/ and docs/LU_EXPLAINED.md

Some scripts assume a Linux server layout under /opt/lu; change the paths for your machine. If you code with an AI, point it at AGENTS.md or use the prompts on Build with your AI.

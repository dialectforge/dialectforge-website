Terminal / SSH

Server administration with SSH carried over DialectForge. There are two versions: the current macOS and iPad apps, which use an earlier protocol that scrambles traffic but does not encrypt it, and a new command-line version (dft and dftd) that is in testing and not yet released.

§ 1 Compare

Standard SSH · ssh root@server

  • Known port 22
  • Recognizable SSH handshake
  • Port scanners find it fast
  • Brute-force attempts around the clock
  • Traffic pattern shows admin activity

DF Terminal, current app · dialectforge connect server-eu

  • Non-standard port
  • SSH scrambled with the earlier XOR scheme, which is not encryption
  • The key comes only from values sent in the clear, so anyone who records a session can rebuild it
  • The key does not change during a session
  • TOTP, a session token and a pinned certificate are checked before a shell

§ 2 Layers
L1TOTP code

A time-based one-time code from your authenticator app. New every 30 seconds.

L2Session token

Issued after TOTP, scoped to this one session, not reusable.

L3Certificate pinning

A pinned client certificate. If it doesn't match exactly, the connection is closed. No fallback.

+Earlier DialectForge protocol underneath

In the current app, all of the above runs inside the earlier XOR scheme. It scrambles traffic but is not encryption. Its key comes only from values sent in the clear and does not change during a session, so anyone who records a session can rebuild it.

The current pieces: a Python server-side SSH proxy with a systemd unit, a command-line client, and native macOS and iPad apps, all using the earlier protocol. They are replaced by the new version below once it is released.

Normal SSH is a front door with a good deadbolt. The current app moves the door around back and adds three more locks, but its outer cover is only a sheet, not a wall. The new version is being built to replace that sheet with standard cryptography, and it still needs outside testing.

§ 3 New version

New version: dft and dftd In testing

A new command-line client (dft) and server (dftd) for Linux, macOS and Windows. It is in testing and not yet released, and there is nothing to download yet.

N1Built on the DF-VPN v1 core

A hybrid post-quantum key exchange (X-Wing: ML-KEM-768 plus X25519), AES-256-GCM for the traffic, and new keys on a timer.

N2A front end to standard OpenSSH

It plugs into ssh as a ProxyCommand, so the login is still handled by standard SSH. The server only forwards to the local SSH port. It has no shell of its own.

N3Pinned server keys

The client pins the server's key.

N4Classical authentication

The key exchange is hybrid post-quantum, but authentication is classical, not post-quantum.

Status: tests pass on macOS. Linux and Windows are being tested now. It is self-tested and not yet independently reviewed. It is planned to be released as open source under AGPL-3.0.

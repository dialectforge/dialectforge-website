Hex dumps: a standard VPN vs. the earlier DialectForge protocol used by the current apps.

§ 1 On the wire

What your ISP sees

Here's the same kind of capture a packet analyzer shows, the same kind of tool used to detect and block VPNs. Top: WireGuard. Bottom: an example of the earlier DialectForge protocol used by the current apps. DF-VPN v1 traffic does not look like this yet.

Why it matters

Countries like China and Iran use deep packet inspection to fingerprint and block VPN protocols. If traffic has a recognizable pattern, it can be blocked. The earlier DialectForge protocol, used by the current apps, was designed to avoid a fixed pattern. DF-VPN v1 does not include that traffic shaping yet. It is planned for a later version. None of this has been tested against a real censor.

And if someone injects packets into a DialectForge stream, they don't match the current dialect, so they're designed to be silently dropped.

How it was built

Current apps (earlier protocol): clients were built for macOS, Windows and iOS, with Android in progress. They negotiate a shared dialect over a control channel, wrap every packet in it, and refresh the dialect every 120 seconds. They do not use post-quantum cryptography. They are built on an XOR-seed scheme, and the DF-VPN v1 spec says an XOR keystream must not be used as encryption. DF-VPN v1 (in testing, not yet released) replaces that protocol. None of the released apps run v1 yet. When the code is released you'll be able to work toward running your own server (see Run it yourself). See the protocol for the details.

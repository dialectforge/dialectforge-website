DialectForge VPN Offline

A censorship-resistant VPN built on the DialectForge protocol. The service is offline right now, and the code is being prepared for open-source release under AGPL-3.0.

§ 1 On the wire

What your ISP sees

Here's the same kind of capture a packet analyzer shows, the same kind of tool used to detect and block VPNs. On the left, WireGuard. On the right, DialectForge.

Why it matters

Countries like China and Iran use deep packet inspection to fingerprint and block VPN protocols. If traffic has a recognizable pattern, it gets blocked. DialectForge traffic is designed to look like random noise, so there's no fixed pattern to write a rule against.

How it was built

The client and server negotiate a shared dialect over a control channel, then wrap every packet in it. The dialect refreshes every 120 seconds. Clients were built for macOS, Windows and iOS, with Android in progress. When the code is released you'll be able to work toward running your own server (see Run it yourself). See the protocol for the details.

Where the security comes from

The security comes from standard cryptography: AES-256-GCM for the traffic, and in DF-VPN v1 a hybrid post-quantum key exchange (X25519 + ML-KEM-768). The dialect hopping is an extra layer meant to resist traffic analysis and fingerprinting. It is not the source of the security, and the design doesn't depend on keeping the dialect secret. This is not security through obscurity.

What's been tested

DF-VPN v1 passes 47 of 47 test vectors, 30 of 30 security tests and 41 of 41 leak tests. These are my own runs. All testing so far was done by John Martin himself, with help from AI assistants (Claude and Grok). None of it has been verified by anyone outside of us.

Service status: offline

There's no live DialectForge VPN service right now, and nothing to subscribe to. Existing download links are disabled. Questions: help@dialectforge.com.

§ 2 Run it yourself

Run it yourself

DialectForge LLC doesn't run any VPN servers anymore. The server and client source code will be published as open source under AGPL-3.0 in the repository dialectforge/dialectforge-vpn-oss. It isn't public yet.

What self-hosting involves

PartWhat it is and what it needs
ServerAuth API + VPN handler

A Python (FastAPI) account and device API backed by PostgreSQL, with an installer for Ubuntu 22.04, plus a Python handler that relays the dialect-encoded traffic through a Linux TUN device with NAT. Needs a Linux server with root access and your own TLS certificate.

iOS / macOSSwift apps with a packet tunnel

Xcode and an Apple Developer account with the Network Extension entitlement.

AndroidKotlin app

The Android SDK; builds with Gradle.

Windows.NET 8 app

The .NET 8 SDK and the third-party Wintun driver, which isn't included.

  1. Set up the server

    Install the auth API and database, then run the VPN handler.

  2. Point the clients at it

    The server address is set in the client code, so you change it and build the apps yourself.

  3. Sign and install

    Use your own signing identities and keys. None of the old ones are included.

Not complete yet

Some pieces still need work before this runs end to end. Most importantly, the negotiation service the clients connect to first isn't in the repository yet. There's also no service file for the VPN handler, and some settings are hardcoded. The repository's self-hosting guide lists them. The code hasn't been independently security-reviewed.

The shop's closed, but the plans and the jigs are going on the table so you can build your own. A couple of jigs are still on the bench.

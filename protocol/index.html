The protocol

Engineering notes, written so a non-engineer can follow along. Numbers are design targets unless I say they're measured.

§ 1 Parts

What's in a node

Every endpoint, whether it's a phone, a server, an ECU in a car or a kernel, runs the same small set of parts:

1.1Seed

A 256-bit random value (SHA-256 over hardware entropy). Child seeds are derived with HKDF-SHA256, so the same parent and label always give the same child. Seeds are computed when needed, not stored.

1.2Negotiation agent

A small module (the target is about 256 KB, small enough for a microcontroller) that turns the seed into dialect proposals and settles on a shared one with its peers.

1.3Dialect

The working rule set for one cycle: how identifiers are remapped, how payloads are scrambled, and how frames are laid out.

1.4Cipher

A tiered choice: XOR keystream for tiny devices that need speed, AES-256-GCM where security matters more than microseconds. On the OS side, DFoS includes an experimental Kyber-768 post-quantum module; it hasn't been independently reviewed.

1.5Anomaly monitor

Counts frames that don't fit the dialect, and other odd behavior. Past a threshold it triggers lockdown and a fresh seed.

A seed is like a master key blank. Every other key gets cut from it, the same way every time, so nobody has to carry copies around.

§ 3 Frames

What changes each cycle

Identifiers are remapped from the shared seed. In the simplest form:

remapped_id = base_id ⊕ int(shared_seed) mod address_space
session_key = derive(shared_seed, cycle_n)
payload'    = cipher(payload, session_key)      # XOR fast path or AES-256-GCM

Where the transport has priorities, like CAN arbitration, the remap keeps the order, so the brakes still win the bus. Payloads are mapped through the dialect and then encrypted. Frequent patterns can get short tokens during negotiation, so the dialect doubles as compression and the overhead stays small (the target is under 5% bandwidth).

On a normal network every message wears the same uniform. Here the uniform changes every couple of minutes, and only the two sides know what it'll look like next.

§ 4 Lifecycle

Refresh, reject, lock down, recover

Cyclic refresh. The default cycle is 120 seconds for network links. Other domains tune it: tens of milliseconds for a CAN bus, minutes for LoRa or idle storage. Both sides step forward from the seed, so no key material crosses the wire at refresh time.

Rejecting foreign frames. A frame that wasn't made with the current dialect doesn't decode into anything valid, so it's dropped before it reaches the application. Without the session seed, an attacker shouldn't be able to build a frame that gets accepted.

Lockdown and recovery. When more than 70% of peers flag an anomaly, the network enters a safe state. Recovery takes one device approved with two-factor authentication, then a fresh seed and a full re-negotiation. The idea is that anything an attacker learned about the old dialect stops being useful.

Resilience. Critical messages can be sent as two or three dialect-shifted “echo frames” so a peer can rebuild a damaged one by quorum. Replay is countered with rolling nonce hashes.

§ 5 Domains

How each transport gets a dialect

The protocol is designed to sit on top of existing standards rather than replace them. Here's what's designed to hop on each one. The WiFi, Bluetooth, Ethernet and LoRa mappings are designs, not shipped implementations; CAN bus exists as a browser simulation.

RefDomainWhat changes each cycleCycle
5.1WiFi · 802.11

Seed shared inside management-frame-protected association frames. MAC addresses and frame types hop; payloads are XOR-shifted. Cycles are coordinated through beacons.

5.2Bluetooth · BLE

Seed set during LE Secure Connections pairing. Device address (BD_ADDR) and GATT handles hop, so a tracker can't simply follow one fixed address, and data goes out as short session bursts. This is also the link for a planned phone companion that holds keys in the phone's secure hardware.

5.3Ethernet

Bootstrapped over LLDP. VLAN tags and EtherTypes cycle, timed with PTP.

Files are stored as dialect-mapped, encrypted blocks. Seeds branch from root to volume to directory to file, so one subtree can be revoked without touching the rest. In DFoS this is a native kernel filesystem, not FUSE: encrypt on write, decrypt on read, invisible to applications. DFoS →

Targets, not guarantees

Design targets across domains: under 500 µs processing overhead, under 5% bandwidth overhead, under 1 mJ per negotiation on an ARM Cortex-M7. Real numbers will come from the open source release and people measuring it themselves.

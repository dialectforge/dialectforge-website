Automotive · CAN bus Design & simulation

What the DialectForge protocol is designed to do on a vehicle's internal network, and how far it actually is. Short answer: it's a design and a simulation. It hasn't been run on a real vehicle or real ECU hardware.

§ 1 Problem

Why CAN bus

CAN (Controller Area Network) is the bus most cars use to connect their electronic control units (ECUs): engine, brakes, body, infotainment. Classic CAN was designed for reliability on a closed network, not for security. A frame carries an identifier and up to 8 bytes of data, and there's no built-in field that says who sent it. Security researchers have published work showing what's possible once someone gets access to a vehicle's bus.

The industry has its own answers to this, such as AUTOSAR SecOC message authentication, gateways and intrusion detection. DialectForge isn't a replacement for those. It's an idea I've been working through: what happens if the bus itself speaks a dialect that changes over time?

Picture a job site where anyone who walks on can shout orders and every crew does what it's told, because nobody checks who's talking.

§ 2 Design

What it's designed to do

  1. Seed at ignition

    When the vehicle starts, a high-priority frame (ID 0x000) is designed to share a 256-bit seed with every participating ECU, before normal traffic starts.

  2. Negotiate a dialect

    Each ECU's negotiation agent turns the seed into a shared dialect: how IDs are remapped and how payloads are scrambled. The target size for that agent is about 256 KB, small enough for automotive microcontrollers. That's a target, not a measurement.

  3. Hop IDs, keep priority

    CAN IDs also decide which frame wins the bus, so the remap is designed to keep the priority order: brake messages should still beat infotainment messages. IDs move every cycle, with a target of 50 to 500 ms.

  4. Drop what doesn't fit

    A frame built without the current seed shouldn't match a valid ID or decode to a valid payload, so ECUs are designed to drop it and raise an anomaly score. Past a threshold, the design calls for a fresh seed and a new dialect.

Every crew gets a code word at the start of the day, and the code word changes through the day. Orders without today's word get ignored.

§ 3 Status

What's real and what isn't

StatusItem
DesignThe CAN mapping

Seed at ignition, priority-preserving ID hopping, payload scrambling and lockdown, as described above and on the protocol page.

SimulationA software simulation of a multi-node bus

Earlier versions of this page had an animated browser simulation of negotiation, an injected frame, lockdown and re-keying. It was a scripted visual demo, not a test on hardware. Timing numbers it showed were targets, not measurements.

Not doneHardware, vehicles, certification

It hasn't run on real ECUs or in a vehicle. Nothing has been safety-assessed or certified (for example under ISO 26262), and there are no automotive partners or customers.

§ 4 Limits

Known limitations

  • Space is tight. Classic CAN frames carry 8 bytes of data. Any scrambling, counters or authentication have to fit in that, or move to CAN FD.
  • Scrambling isn't authentication. The XOR fast path hides values but doesn't by itself prove who sent a frame. A real deployment would need proper message authentication.
  • Timing is safety-critical. Brakes and steering can't wait. Negotiation, re-keying and lockdown would have to be proven safe under real bus load, and that hasn't been done.
  • Every ECU has to take part. Cars contain ECUs from many suppliers. This only works if all participating ECUs run compatible firmware, which isn't something an outside party can just add.
  • The seed has to stay secret. If an attacker can read the seed from an ECU or catch the ignition broadcast, the protection is gone. Key storage in ECUs isn't designed out here yet.
  • Diagnostics have to keep working. Mechanics, inspections and OBD-II tools need access. The design intends to gate that access, not break it, but the details aren't worked out.
  • Not independently reviewed. No one outside DialectForge has tested this design.

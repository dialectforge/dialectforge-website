DFoS · DialectForge OS · v1.0 “Troposphere”

Linux, rebuilt around one protocol.

DFoS is a fork of the Linux 6.12 kernel with DialectForge as a kernel subsystem, not an app on top. Every process gets its own dialect seed. Memory pages are encrypted with keys derived from it. The filesystem and the network sockets speak dialect natively. It's an experimental, one-person project. Its security design has not been independently tested or reviewed, so treat it as a research build, not as a hardened OS.

§ 1 Stack

Every layer is designed to be dialect-aware

Normal Linux trusts every program the same way and keeps memory readable. DFoS is designed to give each program its own key and scramble its memory with it, so one program can't just read another's. Whether it holds up is what testing has to show.

§ 2 Inside

What's in the kernel

2.1Hierarchical seeds

An HKDF-SHA256 derivation tree. The root seed branches into volume, directory and file seeds. Every process inherits a unique dialect at fork().

2.2df_mem: dialect-encrypted memory

Memory pages are encrypted with dialect-derived keys: AES-256-GCM on the secure path, an HMAC-SHA256 keystream on the fast path. It's designed so userspace programs don't need changes. The aim is that a memory dump, a cold-boot capture or a read of another process's memory turns up ciphertext.

2.3dialectfs

A native, stacking VFS filesystem in the kernel. Files are encrypted on write and decrypted on read using the seed tree, designed so applications don't need changes. A related Integrity Shield attests files with DF HMACs.

2.4AF_DIALECTFORGE sockets

A kernel socket family, so programs can open DF-native connections the same way they'd open TCP. The df_tunnel daemon uses it for DF-to-DF links.

2.5Three-tier trust: Native, Adopted, Quarantine

Enforced by a Linux Security Module with ten hooks covering exec, file open, IPC, ptrace and sockets. Packages installed with dfpkg are GPG-verified and given a seed in the Adopted tier. Untrusted processes get short-lived seeds that can be revoked together. USB devices are designed to start in the Quarantine tier.

2.6Anomaly detection

Per-process behavior scoring: socket creation, blocked file access, cross-dialect ptrace. Past a threshold, the process is designed to be locked down automatically.

2.7Hardened image

Configured with key-only SSH, a default-drop firewall, a reduced set of SUID binaries, /dev/mem removed, and a GRUB password on the boot entries that can turn memory protection off.

§ 3 Status

Where it stands, honestly

  • DFoS v1.0 is an experimental build. It boots and runs the DF subsystem described above.
  • It has not been independently tested, reviewed, audited or certified by anyone. Earlier versions of this site repeated security claims that were only an AI chatbot's opinion of the design. Those claims are gone. Nobody has shown that DFoS resists any particular attack, including known Linux exploits.
  • It's built on a standard Linux 6.12 kernel, so it should be expected to share Linux's vulnerabilities unless and until testing shows otherwise.
  • The image includes demo programs that run classic attacks (stack overflow, shellcode injection, cold-boot dump, /proc/pid/mem scraping, ROP) against the DF subsystem. They're demonstrations I wrote myself, not an independent test.
  • Don't use it to protect anything that matters.

Review it

The source is being prepared for open-source release. Once it's out, I'd welcome review from anyone who knows kernels and security. If you find a problem, in the design or in the code, please tell me how. That's how it gets better.

Experimental imagesSend a finding

I built a lock and I'm asking people who know locks to look at it. Until they have, it's just a lock I built, not a proven one.

§ 4 Roadmap

Three layers of atmosphere

LAYER 1

Troposphere v1.0

The Linux 6.12 fork described above. CLI-only base image.

LAYER 2

Mesosphere In development

The same kernel with Rust userspace tools and a full desktop. A build was published in April 2026 as a snapshot of work in progress; it isn't finished.

LAYER 3

Stratosphere In development

A clean-room operating system kernel written from scratch in Rust. DF isn't added on: the DF tunnel is how processes talk at every level, and a program can only do what its seed derivation allows. Other operating systems would run inside it as DF virtual machines.

MOBILE

DFoS Android Planned

A hardened Android base with DF at every layer: AF_DIALECTFORGE sockets, dialectfs over app data, Native / Adopted / Quarantine trust tiers for apps enforced at the IPC layer, and post-quantum key exchange in the kernel as a design goal. To be released under the GPL like the rest of the kernel work.

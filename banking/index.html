Banking · wire transfers Demo

How the DialectForge protocol is designed to carry messages between two banking systems, and what happens to a forged one. This is a demo to explain the idea. No bank uses it, and it hasn't been tested against a real payment system.

§ 1 Idea

What it's designed to do here

Banks still run a lot of core systems on mainframes, often in COBOL, and move payments between each other as structured messages (for example the SWIFT MT103 format for a customer transfer). Those links already use encryption and dedicated networks. DialectForge would be an extra layer on the link between two systems, not a replacement for any of that.

The idea is the same as everywhere else on this site. The two ends share a seed, agree on a dialect, and wrap each message in it. A message that wasn't built with the current dialect, like a forged transfer someone injects into the link, is designed to fail to decode and be dropped. Repeated failures raise an anomaly score and trigger a fresh seed.

Two offices that only accept paperwork written in this week's private shorthand. A forged form in plain English gets set aside, and someone gets told about it.

§ 4 Limits

Known limitations

  • It's an extra layer, not the security model. Payment systems rely on authentication, signing, fraud controls and audit trails. DialectForge doesn't replace any of those.
  • Fast path vs. strong path. The demo showed the XOR fast path. For anything financial you'd want the authenticated AES-256-GCM path, and messages would still need proper signing.
  • Lockdowns have a cost. Dropping traffic and re-keying on an anomaly could delay real payments. How that should work operationally isn't designed yet.
  • Key handling isn't worked out for banks. Where seeds live, who can rotate them, and how that fits existing key-management rules are open questions.
  • Not tested or reviewed. Nobody outside DialectForge has tested this, and there are no performance measurements for this use.

If you work on payment systems and can see where this would or wouldn't fit, I'd like to hear from you: info@dialectforge.com.
